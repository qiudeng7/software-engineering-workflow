# Work entrypoint

Read `README.md` for the project and usage.
Read `CONTRIBUTING.md` for setup, validation, and submission rules.
Read `docs/architecture.md` for the code map, boundaries, and invariants.

## Start a task

Read the target issue, its latest handoff, and linked decisions. Check the current branch, commit, and worktree. Read only the code and records relevant to the task, expanding when evidence requires it.

Before changing code, identify the goal, acceptance criteria, likely modules, constraints that must remain true, and assumptions still needing verification.

## During work

Keep confirmed facts, accepted constraints, and unverified hypotheses distinct. Do not change accepted scope or design silently. Keep changes reviewable and update canonical documentation when behavior, interfaces, boundaries, or development commands change.

## Finish or pause

Report checks actually run and those not run. If unfinished or transferring ownership, add a recoverable handoff to the issue. Move durable knowledge into its canonical document instead of leaving it only in chat.
