# 需求分析图文组织：反例

下面以同一个“添加模型广场和聊天试用”需求展示图只是文字附件的写法。

```markdown
## 功能需求

用数十条文字完整描述广场、聊天、切换、计费和会话规则。

## 异常处理

再用一张大表完整描述所有异常。

## 相关图示

[功能图]
[页面图]
[流程图]

## 图示说明

逐项复述图中的节点、箭头和分支。
```

问题不在文字绝对数量，而在于：读者不看图也已经读完了全部分析；看图反而要再读一次。

应按读者理解需求的顺序穿插图片，让图承担主要表达，而不是在完整文字分析后集中附图，再复述图片。参见[正例](demo-requirements-visual.md)。
