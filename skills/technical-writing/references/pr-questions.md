# PR 参考问题

目标读者是判断本次变更能否接受的审阅者。关联 Issue 可作为阅读材料，送审时提供可访问链接；不要求 PR 重复完整需求和设计。

- 这次实际改变了什么，对应哪个目标或 Issue？
- 哪些部分已经完成，哪些尚未完成或明确不在本 PR 中？
- 实际实现与既定方案有什么偏差，依据是什么，是否需要确认？
- 运行了哪些验证，结果和证据在哪里？哪些未运行，有何影响？
- 有哪些兼容、迁移、部署风险，接受或上线前需要处理什么？
- 审阅者应重点判断什么，是否还有阻断合并或交付的问题？

例如，PR 声称“模型调用链路已打通”时，可以问“哪些证据证明实际请求和费用结算可用，哪些只是配置或单元测试验证？”不要在问题中默认 CI 通过等于部署成功。

对阶段报告，只评估当前阶段承诺及其证据，不要求提前证明后续阶段完成。对于无相关风险的小改动，不要求编造迁移、回退章节。
